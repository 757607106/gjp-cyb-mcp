# MCP 可靠性优化与 AgentScope 2.0.7 升级

> 历史记录：本文档成稿时框架为 AgentScope 2.0.7；此后基础设施已迁移至
> MCP Python SDK（见 `AGENTS.md` 技术栈），可靠性结论与重试边界仍然适用。

本次在现有工具接口和业务流程基础上修复可靠性缺口，框架精确锁定稳定版 `agentscope==2.0.7`，同步更新 uv.lock。仅使用正式稳定版本，不采用 dev 或其他预发布版本。

参考：[AgentScope 2.0.7](https://docs.agentscope.io/versions/2.0.7/zh)、[ERP API](https://test-ai.yuncyb.com/aicyberp-api/v3/api-docs)。此前的 mcp-review-2026-09-10.md 记录优化前状态，本文件记录落地范围。

## 本次完成

- API Key 以 SHA-256 摘要参与身份隔离，原文继续只交给凭据存储与 ERP 请求头；同 Key/不同 Key 的隔离语义不变，常规 tenant/account 日志不再泄漏 Key。
- 生产 JWT 明确要求 exp、tenantId、loginId，并拒绝空或非法类型的身份字段；本地 JWT、API Key 两种现有接入方式保留。
- 同会话提交使用异步互斥锁，防止同 key、不同 key 并发消费同一预览。取得远端成功 ID 后先记成功并消费预览，再回查业务单号，避免回查取消后重复创建。
- 提交网络异常、服务端 5xx、成功响应结构异常或创建阶段被取消时，保留该预览的结果未知状态；同一预览不再直接重发。明确业务拒绝仍可按原方式重试。提示词区分明确失败与结果未知，要求先核对 ERP。
- 新增/修改的商品数量校验有限数及 API 下界 0.0001；单价、优惠、收款金额校验非负有限数；超大金额计算返回业务错误。正常数值和金额计算方式不变。
- 商品目录首次并发加载去重，后台刷新避免重复入队并复核失败冷却；服务关闭先取消并等待刷新任务，再关闭共享 HTTP 客户端。
- MCP 对非 dict 原始返回只执行一次工具；日志区分业务 ok 状态，清理“工具只改本地草稿”的过时注释。

## 后续契约修正（2026-09-17）

真实 ERP Bearer 由可信 AI 平台直接传入，使用 `eff` 而不是标准 `exp`，且 ERP 的
HS256 签名密钥不分发给 MCP。为恢复既有对接契约，legacy 入口取消部署级
`ERP_BILLING_JWT_SECRET` 和本地签名校验，改为校验 JWT 结构及 `tenantId`、`loginId`
字段后原样透传，由 ERP API 做最终鉴权。相应部署边界改为：legacy `/mcp` 必须通过
私网、网关访问控制或来源白名单只对已完成鉴权的可信平台开放。

## 保留的既有行为

十个工具的名称、输入/输出 Schema 和工具标记与修改前一致。默认保存类型、确认参数、商品匹配与别名、候选排序及去重、部分开单、图片/语音文本来源、API 路径、多份预览和查询分页逻辑保留。

没有直接迁移已废弃的商品兼容 API，当时没有收紧 update 的 pre_receipt 枚举（已在 2026-09-11 核对 ERP 契约后修正），也没有改造对话 ID 截断、环境名回退、纯商品搜索的同步策略。这些会改变已有行为或需要额外接口验证，不在本次保持业务兼容的优化中处理。自然语言解析的自定义单位空格分隔、负号和连续“各”词组问题保留为已知限制，不能声称已全部修复。

## 部署与重试边界

- legacy JWT 必须包含有效 `tenantId`、`loginId`；有效期及签名由可信接入方和 ERP
  校验，MCP 不把 payload 解析当作独立认证。
- API Key 的摘要是内部隔离键，不代表 MCP 验证了 Key 的有效性；真实权限继续由 ERP 校验。
- 预览、成功缓存和结果未知标记仍在单进程内存中；多 worker/多副本不自动共享状态。当前按单进程部署，不增加 Redis 或分布式锁。
- 结果未知时先查单确认；若 ERP 已创建则使用查回的单号，确认未创建后才能重新预览开单。重启、会话淘汰、另建预览都不提供持久防重保证。完整跨进程幂等仍需 ERP 业务键支持。
- 未增加预览自动过期/新预览废弃旧预览策略，也未改变既有模型确认机制。
- 本次 Key 只通过测试进程环境变量传入，不写入仓库和配置文件；生产部署仍需自行注入凭据。

## 验证

- 真实 ERP 测试环境：53 项端到端测试通过，覆盖十个工具、草稿转正式、正式开单、修改、作废、幂等、会话隔离和超时；本轮创建单据均按测试流程作废。
- 单元与离线回归：229 passed、53 skipped、4 xfailed；53 项 E2E 已另行全部执行通过。原先四项预期失败（零数量、超大数量、两类并发提交）已转为正常回归；剩余四项预期失败仍记录保留的解析及工具层校验限制。
- 对比修改前后十个工具的名称、输入/输出 Schema、只读和并发标记，完全一致；验证 AgentScope 2.0.7 标准调用与 MCP 原始调用返回一致。
- Ruff 与 diff 格式检查通过；wheel 构建成功，元数据锁定 AgentScope 2.0.7，制品未包含 tests/docs/config/AGENTS.md。
