# ADR 0005：MCP 2026-07-28 与 Python SDK v2 发布边界

- 状态：已采纳
- 日期：2026-09-21

## 背景

旧发布层固定使用 `mcp>=1.28,<2`，只能协商到 2025-11-25，并通过
`_tool_manager`、`_mcp_server` 等私有属性覆盖工具 Schema 和调用处理。
官方 2026-07-28 Python 教程要求 SDK 2.0.0 以上，SDK v2 同时支持新的
逐请求协议和旧版握手回退。

ERP 业务层已经稳定维护 59 个场景工具、会话隔离、预览确认和幂等逻辑；协议
升级不应触发业务工具重写。

## 决策

1. 依赖使用 `mcp>=2.2,<3`，以 `MCPServer` 作为服务入口。
2. 保留 `SessionFunctionTool`、`SessionToolSet`、Port 和 Adapter；仅替换
   `gjp_common.mcp` 发布适配层。
3. 通过 SDK 明确支持的 `MCPServer.list_tools()`、`call_tool()` 覆写点发布
   手工业务 Schema，不再访问 SDK 私有管理器或 low-level handler。
4. 输入继续按已发布 JSON Schema 校验；业务返回结构保持不变，但
   `ok=false` 在 MCP 层映射为 `isError=true`。
5. Streamable HTTP 同时启用 2026-07-28 和 SDK 提供的旧协议回退；保持
   `stateless_http` 与 JSON response 模式。
6. DNS rebinding 防护保持开启。公开 Host 和浏览器 Origin 必须显式加入
   `GJP_MCP_ALLOWED_HOSTS`、`GJP_MCP_ALLOWED_ORIGINS`；WorkBuddy 从其公网
   base URL 自动补入白名单。
7. 直连接口在进入 MCP 协议处理前拒绝缺失、格式错误或已过期的 Bearer
   凭据，并同时接受 `X-API-Key`。WorkBuddy 继续使用其 OAuth
   保护中间件。
8. 未知工具抛出 JSON-RPC `INVALID_PARAMS`，不返回伪成功的工具结果。
9. 两个最终 ASGI 入口在认证层外统一按凭据摘要限流；生产分别提供 WorkBuddy OAuth
   与直连 ERP Bearer Token / `X-API-Key`。

## 未采用方案

- 不把 59 个工具重写成 59 个新的装饰器函数：这会复制业务签名和 Schema，
  增加迁移风险，且不改善业务能力。
- 不继续修改 SDK 私有属性：v2 已改变私有对象结构，后续升级不可控。
- 不在本次升级中改变 preview、update、void 或 ERP payload 语义：这些属于
  独立业务契约变更，应另行设计和验收。

## 结果

- 新客户端可直接使用 MCP 2026-07-28；旧客户端仍可协商 2025-11-25。
- 工具名称、输入输出 Schema、展示结果和 ERP 调用逻辑保持不变。
- 参数和业务错误可由 MCP 客户端通过 `isError` 正确识别。
- 生产部署必须配置真实公开 Host；未配置的 Host 或 Origin 会被明确拒绝。
